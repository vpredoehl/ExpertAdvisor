# LSTM training-objective provenance

## Phase 4A contract

Phase 4A names and persists the objective already used by the production LSTM
training path. It does not add an auxiliary head, regression loss, new target,
new gradient, or new inference behavior.

The canonical legacy identifier is
`legacy_first_hit_weighted_ce_v1`. Its current deterministic identity is
`fnv1a64:65818f2e1fa1a324`. The complete canonical text is generated by
`EA::TrainingObjective::CanonicalText(EA::TrainingObjective::Legacy())` in
`Headers/TrainingObjective.hpp`; the canonical text, not the hash alone, is the
authoritative contract.

The legacy contract records:

- the three-class `UpNeutralDownReturn` high/low first-hit target, with Down,
  Neutral, and Up class indices 0, 1, and 2;
- strict threshold comparisons and the existing Up-wins same-bar tie rule;
- true-class-weighted softmax cross-entropy with class weights 1/1/1 and a
  probability floor of `1e-12`;
- the `0.1` classification-logit gradient scale and `4.0` classification
  shared-core gradient scale;
- weight-sum normalization for the internal loss and all accumulated
  gradients, and example-count normalization for the scalar returned by
  `CalculateBatch`;
- double recurrent-core gradient accumulation, float head-gradient
  accumulation, and double scalar-loss accumulation;
- componentwise clipping to `[-10, 10]` after normalization;
- plain SGD updates, no weight decay, and skip-on-nonfinite-gradient behavior;
- disabled auxiliary loss, zero auxiliary coefficient, no regression target,
  no robust loss, no target clipping, and classification-only shared gradients.

Per-experiment values such as prediction horizon, label threshold, window size,
class weights, normalization version, trained epoch count, and core/head
learning-rate multipliers remain in the established experiment columns and
`train_config_meta`. The objective contract complements that metadata; it does
not replace it.

## Experiment and model identity

Migration `079_training_objective_provenance.sql` adds the canonical objective
and its hash to each experiment and to the practical experiment uniqueness
key. Historical rows receive the exact legacy defaults. Recommendation
semantic configuration v19 also includes objective canonical text and identity;
older v18 and earlier canonical identities retain their historical parsers.

Every newly saved model/checkpoint stores
`training_objective_canonical_meta` and `training_objective_hash_meta` through
the existing matrix metadata repository. A model with neither marker predates
configurable objectives and deterministically resolves to the legacy contract.
A model with only one marker, a corrupt hash, or unsupported canonical text
fails closed.

## Resume compatibility

Ordinary resume requires exact canonical objective equality and matching
deterministic identity. The check occurs when a resume source is selected and
again before the training runtime loads it. Consequently, a changed objective
mode, auxiliary coefficient, normalization rule, loss version, robust-loss
definition, clipping rule, or any other canonical field is not an ordinary
compatible resume.

Phase 4A exposes no warm-start exception. Historical marker-less models resolve
to legacy and are compatible only with a requested legacy objective.

## Loss normalization note

The existing training path has two scalar loss contracts:

1. The internally printed classification loss is weighted loss sum divided by
   true-class weight sum.
2. The first scalar returned by `CalculateBatch` is the same weighted loss sum
   divided by `mseCount`, which is the number of examples.

They are equal with the current 1/1/1 class weights and diverge for non-unit
weights. Gradients are divided by true-class weight sum. Phase 4A freezes and
names this behavior; changing it would change training mathematics and is
therefore deferred to a separately reviewed correction.

## Phase 4B/4C extension boundary

The configuration reserves typed auxiliary-loss, regression-target,
normalization, robust-loss, delta, clipping, and coefficient fields, but Phase
4A validation requires the classification-only legacy values. A later phase
must add a new supported mode/version, canonical parser, database constraints,
model metadata compatibility rules, deterministic loss/gradient tests, and an
explicit execution path before any auxiliary gradient can become active.

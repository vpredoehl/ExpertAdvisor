Domain contract

Design an immutable typed review value that binds exactly:

- review contract version;
- persisted follow-up proposal ID;
- exact Phase 6A proposal contract version;
- exact proposal canonical text;
- exact proposal identity hash;
- review decision;
- reviewer identity;
- reason text.

Canonical identity must be deterministic and locale independent.

Canonical text is authoritative.

The tagged hash is only an accelerator.

Exclude from review identity:

- database review-event ID;
- creation timestamp;
- process ID;
- CLI formatting;
- scheduler state;
- any later activation or execution state.

Validation requirements

Fail closed for:

- unsupported review contract version;
- invalid or missing persisted proposal ID;
- malformed proposal canonical/hash pair;
- invalid review decision;
- empty or invalid reviewer identity;
- empty or invalid reason text;
- canonical text containing NUL;
- review canonical/hash mismatch;
- disagreement with the persisted Phase 6B proposal;
- attempts to encode activation, execution, queue, scheduler, experiment, or
  authorization state.

Use stable explicit error reasons.

Repository behavior

The repository must:

1. Accept only the immutable typed Phase 6C review contract.
2. Verify the referenced persisted Phase 6B proposal exists.
3. Verify exact proposal ID, contract version, canonical text, and hash.
4. Serialize concurrent review attempts for the same persisted proposal.
5. Return `recorded` for the first valid review.
6. Return `existing_identical` for exact replay.
7. Return a deterministic conflict for a different decision, reviewer, reason,
   or review identity for the same proposal.
8. Reload into an immutable typed review value.
9. Validate all persisted fields and complete canonical identity on reload.
10. Never update or supersede an existing review event in Phase 6C.

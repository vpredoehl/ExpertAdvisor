GOAL
Add a production-quality, persisted, deterministic feature-ablation mechanism so matched experiments can measure individual feature contribution without changing Tensor layout, historical model-input widths, or feature semantics.

This is infrastructure, NOT a new feature increment.

CORE DESIGN
Implement named feature ablation while preserving the physical feature vector.

An ablated experiment MUST:
1. Build the same Tensor/model input width as an otherwise identical non-ablated experiment.
2. Deterministically replace selected feature values with exactly 0 before they are consumed by the model.
3. Apply the identical mask during training, checkpoint inference, normal inference, resumed training, resumed inference, and any other real model-input path.
4. Persist the ablation specification as experiment/model provenance.
5. Include the ablation specification in experiment identity/deduplication wherever necessary.
6. Default all historical/existing experiments to no ablation.
7. Never reinterpret historical n_in widths.
8. Never change Tensor feature_size merely because a feature is ablated.

STABLE FEATURE IDENTITIES
Do NOT make raw numeric Tensor column numbers the primary persisted user-facing identity.

Introduce a stable canonical feature identity registry for ablatable appended features. Prefer canonical names corresponding to semantic features, for example names along the lines of:
- relative_tick_volume
- rms_return_surprise
- volatility_regime
- directional_range
- close_location
- directional_efficiency
- return_sign_persistence
- return_direction_imbalance
- directional_adverse_excursion

Inspect the actual current feature layout and use repository-consistent canonical names.

The registry must map canonical feature identity -> current Tensor/model-input location and validate whether that feature exists for the experiment/model input contract.

Do not silently accept unknown names.
Do not allow duplicate names to alter semantics.
Canonicalize ordering so logically identical masks have identical persisted identity.

INITIAL SCOPE

Do not automatically expose legacy columns 0..31 unless the architecture makes that safe and clearly named.
Do not ablate the four model return features in this increment unless they already participate naturally in the same stable feature registry and doing so is demonstrably safe. Document them as future scope otherwise.

MODEL PROVENANCE

TRAINING/INFERENCE APPLICATION POINT
Find the single safest shared point at which the final model input vector can be masked so training and inference cannot diverge.

Prefer one shared helper/function used by all model-consumption paths rather than separate ad hoc masking implementations.

Required semantic order:
1. Construct the normal feature vector exactly as today.
2. Project according to the model's historical/current input contract exactly as today.
3. Set selected ablatable feature positions to exactly 0.
4. Feed the resulting unchanged-width vector to the model.

If actual architecture requires masking before projection, prove historical-width correctness and ensure a feature that does not exist in that historical prefix cannot be ablated silently.

Masking must not mutate persistent Tensor history/state or affect computation of later causal features. It only changes the model-consumed input value.

IDENTITY / DUPLICATE DETECTION

RESUME / RETRY SAFETY
This is critical.

A resumed training run must use the same canonical ablation mask as the model/checkpoint lineage being resumed.

Reject attempts to resume a model/checkpoint with a different ablation mask unless there is an explicit future mechanism designed for that purpose.

Retry-failed and checkpoint-resumability paths must preserve the mask exactly.

INFERENCE SAFETY

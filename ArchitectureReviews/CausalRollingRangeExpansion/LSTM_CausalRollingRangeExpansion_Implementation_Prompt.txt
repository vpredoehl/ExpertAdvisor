# LSTM Causal Rolling Range Expansion / Compression Feature — Implementation

## Objective

Implement one small, production-quality causal LSTM input feature:

**causal rolling range expansion / compression**

The feature measures whether the recent short-horizon price envelope is expanded or compressed relative to a longer trailing price envelope.

This is intended to complement, not duplicate:

- causal volatility regime
- causal multi-bar range pressure
- causal directional range
- causal close location
- causal directional efficiency/persistence
- causal return-direction features

This is the final planned predictive feature increment before feature contribution is evaluated through the formal feature-ablation mechanism.

Work directly in the current repository. Inspect the existing production feature pipeline and follow its established conventions rather than creating a parallel implementation.

## Required semantic definition

Use two fixed causal windows:

    short lookback = 8 bars
    long lookback  = 32 bars

For completed bar `t`, including the current completed bar:

    short_high_t = max(high[t-i]), i = 0..7
    short_low_t  = min(low[t-i]),  i = 0..7

    long_high_t = max(high[t-i]), i = 0..31
    long_low_t  = min(low[t-i]),  i = 0..31

Define:

    short_range_t = short_high_t - short_low_t
    long_range_t  = long_high_t - long_low_t

The raw relative range ratio is:

    ratio_t = short_range_t / long_range_t

Because the short window is contained within the long window, under ordinary finite inputs:

    0 <= ratio_t <= 1

Map this to a centered scalar:

    range_expansion_t = 2 * ratio_t - 1

Interpretation:

    approximately -1 = strong local compression
                  0 = short range is 50% of long range
                 +1 = short range equals long range

Use this centered form as the tensor feature.

## Degenerate-range behavior

If the long-window range is zero or effectively zero, return the neutral value:

    0.0

The result must always be finite.

Use the repository's established numerical-safety conventions for determining an effectively-zero denominator. Do not introduce an arbitrary absolute epsilon if an existing scale-aware convention is available.

If floating-point roundoff produces a ratio microscopically outside [0,1], handle it deterministically and safely according to existing conventions.

Do not use clipping to hide substantive implementation errors.

## Window semantics and warmup

Both windows are strictly causal and include the current completed bar.

At time `t`, no observation after `t` may influence the result.

During startup, use the completed history actually available, consistent with the existing causal feature architecture.

Thus before 8 completed bars exist, the short range uses the available completed bars.

Before 32 completed bars exist, the long range uses the available completed bars.

Do not manufacture synthetic history.

Do not introduce a new feature-warmup policy.

The feature must respect the repository's existing `feature_warmup_scope` and tensor construction behavior.

## Relationship to existing volatility feature

This feature is NOT another RMS-return volatility feature.

The existing causal volatility-regime feature measures behavior derived from returns.

This feature measures the geometric high-low price envelope:

    recent 8-bar high-low range
        versus
    trailing 32-bar high-low range

Do not modify or replace the existing volatility-regime feature.

Document this distinction in the implementation report.

## Relationship to multi-bar range pressure

The recently implemented multi-bar range-pressure feature answers:

    "Where is the current close inside a trailing price range?"

This new feature answers:

    "How wide is the recent short price range relative to the longer price range?"

The two features must remain independent.

Do not modify the semantics of `multi_bar_range_pressure`.

REVIEW AREAS

1. Canonical policy representation

Verify that ranking-policy canonical text includes every semantic policy field and version needed to reproduce behavior.

Check:

- exact field order

- explicit versioning

Confirm hashes are accelerators only and canonical text remains authoritative.

2. Scope canonicalization

Review all seven scopes:

- evaluation run
- recommendation scan
- symbol
- horizon
- family
- symbol plus horizon
- explicit global

Verify:

- exactly one scope is represented
- canonical text distinguishes every scope type
- NULL and absent filters are stable and unambiguous
- explicit global cannot collide with an empty or malformed specific scope
- text values are length framed or otherwise delimiter safe
- identifiers cannot collide through formatting
- control characters and leading/trailing whitespace are rejected consistently
- scope canonicalization agrees with repository filtering and persisted snapshot columns

Attempt adversarial values containing:

- commas
- semicolons
- colons
- equals signs
- percent signs
- multibyte UTF-8
- embedded words such as NULL or global
- common prefixes

3. Source-membership canonicalization

Verify membership identity includes the complete selected Step 1 evidence membership.

Check:

- deterministic sorting
- evaluation identity canonical text

- count
- byte length versus character length
- member ordinal
- exact end-of-input behavior
- duplicate evaluation-result rejection
- duplicate canonical identity handling
- malformed or empty membership behavior
- maximum input boundary

Attempt to construct canonical collisions using:

- one identity containing serialized member-like text
- result IDs with decimal-prefix relationships such as 1 and 10
- multibyte identities
- empty identities
- duplicated identities with different result IDs
- reordered input vectors
- repeated identical evaluation-result rows

Confirm reordered equivalent input produces the same canonical membership and snapshot identity.

5. Bucket mapping

6. Deterministic ordering

Review comparators for strict weak ordering.

Advisory-ready order:

1. final score descending
2. recommendation semantic hash
3. evaluation identity hash
4. evaluation-result ID

Blocked order:

1. blocked disposition priority
2. recommendation semantic hash
3. evaluation identity hash
4. evaluation-result ID

Non-actionable order:

1. non-actionable disposition priority
2. recommendation semantic hash
3. evaluation identity hash
4. evaluation-result ID

Verify:

- equal floating-point values
- positive zero versus negative zero
- NaN and infinity rejection
- duplicate IDs
- identical hashes with different canonical texts
- hash collisions
- result-ID fallback
- no comparator inconsistency
- no dependency on std::sort instability
- rank assignment and global ordinal remain deterministic

Canonical text, not hashes, must protect correctness where collisions are possible. Identify any place where ordering or equality trusts a hash without checking canonical identity.
